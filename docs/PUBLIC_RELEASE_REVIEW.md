## CI/CD review and correction

The original workflow unconditionally invoked credentialed live evaluation on
pull requests. That made ordinary public/fork PR validation depend on a secret and
could trigger live usage. The existing step now runs only for manual
`workflow_dispatch` with `run_live_evaluation=true` (default false).
Its command, existing quality thresholds, release gates and exit semantics remain
unchanged. Standard CI runs the complete offline suite without secrets on Python
3.11, with dotenv and optional provider telemetry disabled.

Permissions remain `contents: read`. The intentional upload remains limited to
`reports/release_13e4/`, including failure evidence; it does not publish all reports,
local environment files or caches. Core imports are exercised by tests; there is
no distributable package build to validate. Local YAML/condition checks and the
existing release-workflow tests passed during the local audit. Remote GitHub
Actions was not invoked; these results do not establish hosted CI success for
the final v1.0.1 commit.

## Capability and documentation boundaries

The [overview](PROJECT_OVERVIEW.md) records the implemented inventory and external
AutoQE relationship. The [architecture](ARCHITECTURE.md) names execution/evaluation
contracts and explicitly distinguishes runtime ordering from unordered generic
call matching. The [demo](DEMO_GUIDE.md) defaults to synthetic offline evidence
and separate controlled capture/scoring tests. It cannot establish current live
semantic quality or release eligibility.

[Model/prompt comparisons](MODEL_PROMPT_REGRESSION.md) use paired eligible evidence;
directional changes are not significance tests. No confidence intervals, judge
noise bands, repeated-judge uncertainty or calibration are claimed. Fixed quality
gates do not implement statistical noise filtering. Cost calculations require
attributed verified pricing and are not provider invoices. Optional local
observability mapping is not an installed enterprise exporter.
